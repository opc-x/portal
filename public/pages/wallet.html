异常处理

问题方案
链分叉结论：回滚到分叉点重扫，确认数够了才推成功
现象：已推「转账成功」，记录又没了（块被全网作废）
查：新块的 parentHash（父块指纹）对不上上一块
修：流水、游标、待发通知一起退，重扫
防：确认数达标（波场 19）前只显示「确认中」
广播失败结论：原样重发，同一 nonce 只成交一次
现象：广播超时或节点报错，不知道成没成
做：存了签名字节和 txHash，原样重发，可换节点，不重签
安全：nonce（交易序号）锁在签名里，重发只扣一次钱
判断：以扫块看到进块为准
出块失败结论：加速 = 提价重签，取消 = 同 nonce 发 0 给自己
现象：一直没确认，同地址后面几笔按 nonce 排队全卡
原因：gas（手续费出价）低，没人打包（EVM 链，波场无 nonce 另论）
加速：后端算更高的 gas（常见至少高 10%），连同原 nonce 返回；客户端重签，后端广播，同 nonce 顶替
取消：同 nonce 发 0 金额给自己
重签必须在客户端：后端不碰私钥
追块 OOM结论：无界队列撑爆内存，改有界队列 + 背压
现象：停过一阵，重启追块反复被杀（落后追块才爆）
查：堆一路涨，Full GC（全量回收）回收不掉；heap dump 里队列堆了几万个区块
根因：并发拉块快，串行写库慢，队列无界（默认 Integer.MAX_VALUE）
修：① 有界队列容量 N，满了拉取阻塞（背压）② 每块一个任务，写库线程按块高取 ③ 单块超时换节点重拉
结果：内存封顶 N 个块
