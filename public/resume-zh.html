dtcpay ｜ Java 后端 Owner（电子钱包）
2024.04 – 至今
新加坡 MAS 持牌支付机构（法币 + 稳定币）。C 端 App 电子钱包。负责钱包核心链路：充值到账 → 提现出款 → 每日对账；用户余额的每一笔变动都由钱包服务统一记账。
并发安全（防超扣）
多笔扣款同时到，行锁让它们排队；每笔用一条更新语句同时判断余额并扣减，余额不够就扣不动，不会扣成负数（条件更新 + 行锁）。
接口幂等（Redis 令牌）
进支付页先发一次性令牌，提交时 Redis 删掉令牌才处理，连点、重复提交直接挡掉；漏网的靠业务单号兜底，只记一次（唯一索引）。
掉单补偿
渠道通知支付结果时，先验签名、对金额再记账；通知丢了，定时去渠道查单补上。
出款幂等
先冻结余额再让渠道打款；渠道超时不知道打没打，只去查结果、绝不再发一次，防止给用户打两次钱；查到成功才真扣，查到失败才解冻退回。
最终一致性
扣款和“待发通知”写在同一个数据库事务里，要么都成、要么都不成；后台再把通知发出去（App 推送、站内信等），失败就重发。不会出现钱扣了、用户却收不到通知（本地消息表 + Kafka）。

可靠投递 + 幂等消费

钱包地址过滤
